  <name>Task 1: Reconcile interrupted registry mutations from durable intent</name>
  <files>backend/registry_install.go, backend/registry_updates.go, backend/registry_recovery.go, backend/registry_recovery_test.go, backend/launcher_state.go</files>
  <read_first>backend/registry_install.go, backend/registry_updates.go, backend/registry_service.go, backend/launcher_state.go, backend/backend.go, backend/fileutil/atomic.go</read_first>
  <behavior>
    - Killing install or update after the directory swap but before state.json replacement leaves the previous durable record and install directory authoritative on restart.
    - Killing install or update after state.json replacement leaves the new durable record and matching directory authoritative on restart.
    - Killing a same-version reinstall on either side of state.json replacement uses the durable transaction token to choose the old or new directory despite identical version identity.
    - Injecting saveState failure after install or update swap returns an error, never success; the previous durable record and directory remain or an intact journal blocks readiness until recovery.
    - Killing uninstall before durable record removal preserves the old record and directory; killing it afterwards resumes removal, permission/usage/dispatch cleanup, and scope reclaim or reports a safe incomplete-cleanup warning.
    - Recovery is idempotent across a second interruption and refuses to report ready when it cannot establish a record/directory match.
  </behavior>
  <action>Implement D-03 restart reconciliation for install, same-version reinstall, update, and uninstall commit windows. Add a private, bounded, versioned per-napp intent file under the service data directory, written atomically and fsynced before directory swap or record removal. Assign each intent a unique transaction token. Add a non-secret per-napp committed-token map to AppState/state.json and persist the token in the SAME atomic state.json replacement as the installed-record change or removal; a separate marker written after state.json is insufficient. The intent records canonical identity, operation, prior/new version identity, token, and exact bounded directory names; reject path traversal, symlinks, malformed journals, and conflicting duplicate intents. A per-napp busy claim already serializes mutations in-process. Implement a recovery function that compares the journal token with the committed token in persisted state.json: equal means the new side committed, unequal means it did not, including identical-version reinstall. Restore prior directory for an uncommitted swap, retain new directory for a committed swap, and remove unused staging/set-aside directories. For uninstall, keep the directory if token did not commit; otherwise resume idempotent cleanup. Explicitly handle the currently ignored saveState errors in registry_install.go and registry_updates.go: do not return a successful result, restore prior in-memory state and directory when possible, and retain durable intent plus block further mutation/readiness if rollback cannot be completed. Preserve the rollback copy until successful save and reconciliation. Do not claim an RPC success for an operation whose response was lost at forced exit; a later client must inspect installed state. Existing removeStaleStaging must not delete a journaled rollback copy before reconciliation. Delete intent only after durable reconciliation and cleanup. If any required step cannot finish, keep intent and return a safe actionable error. Test unique-token disambiguation for same-version reinstall and fault-inject saveState failures after swap for install/update. Factor interruption hooks at durable boundaries; use child test processes or deterministic filesystem fixtures without killing the parent runner. Preserve atomic state.json writes and prior Phase 7 lease handling.</action>
