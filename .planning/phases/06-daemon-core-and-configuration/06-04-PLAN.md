  <behavior>
    - A ready daemon reports its actual monotonic uptime and len(backend.OpenWindows()), not managed-window history.
    - A failed reload adds a warning and an error summary but does not make readiness false; a successful reload clears the warning.
    - Diagnostics never contain ClientKey, Login, bunker values, raw AppState or absolute private paths.
  </behavior>
  <action>Implement D-11/D-12/D-13 as Service.Health() and Service.Diagnostics() with stable typed, JSON-ready allow-list DTOs, callable by Phase 7 without a transport dependency. Health includes readiness, version, uptime, config status, storage status and active count from backend.OpenWindows(). Readiness means stores initialized, configuration valid and service accepting work, not that a signer is logged in or every network relay answers. Track service start with a monotonic time.Time; record a bounded ring of at most 32 safe recent error summaries with category, time and fixed/sanitized detail. Diagnostics includes health, a defensive effective snapshot of the three allowed settings, warning and recent errors. Never serialize AppState or raw errors from file paths, signers or network clients. Represent sensitive paths in diagnostic DTOs by a documented redacted marker or config basename. After closing begins, health must no longer claim readiness. Test redaction with sentinel secrets and paths injected into lower-level errors.</action>
