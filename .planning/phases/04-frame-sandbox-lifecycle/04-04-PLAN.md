<objective>
Replace the no-op navigation directive on every launcher-served page with policies engines enforce: the napplet host page gets the NIP-5D baseline plus frame-ancestors 'none' (which blocks http(s), meta-refresh and anchor navigations of the napplet frame through frame-src/child-src), napp and settings pages get frame-ancestors 'none', and every loopback response carries X-DNS-Prefetch-Control: off, on desktop and Android alike (SBOX-02; D-05, D-06, D-07, D-08, D-11, D-17).

Purpose: the research spike showed today's header lets a napplet navigate its frame to an attacker page with no CSP whose messages pass the host's source check (RESEARCH H0). The H3 policy blocked every such navigation on WebKitGTK while the srcdoc still loads.
Output: policy constants in backend/webview, a header middleware and extracted handlers in desktop/child with httptest coverage, Android parity through Mobile accessors.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| napplet frame -> navigation | an untrusted document can try to navigate its own frame to any URL |
| other origins / pages -> launcher loopback pages | any page that learns a loopback URL could try to embed it |
| loopback HTTP response -> engine | the policy only binds if it rides the HTTP response (frame-ancestors is ignored in meta) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-17 | Elevation of privilege | napplet frame navigating to an attacker http page that speaks for the napplet (RESEARCH H0 escape) | high | mitigate | host policy frame-src/child-src 'none' on the host page response (Task 1); anything still loaded is rebuilt by 04-01 |
| T-04-18 | Tampering | clickjacking or embedding of loopback pages | medium | mitigate | frame-ancestors 'none' on every loopback response, desktop and Android (Tasks 1-3) |
| T-04-19 | Information disclosure | DNS prefetch from launcher pages | low | mitigate | X-DNS-Prefetch-Control: off on every response (Tasks 1-3) |
| T-04-20 | Denial of service | host policy stricter than the napplet's breaking every napplet (RESEARCH C1) | high | mitigate | NappletHostCSP derived from NappletCSP; TestNappletHostCSP proves per-directive equality (Task 1) |
| T-04-21 | Tampering | desktop/Android policy drift | medium | mitigate | single source in backend/webview, Mobile accessors (Task 3) |
| T-04-22 | Tampering | backend dev server (backend/dev.go) serving dev napps without these headers | low | accept | dev builds only, napp pages (not napplets), outside the child; recorded in the SUMMARY |
</threat_model>
