<objective>
Close the network channels that bypass connect-src wherever the webview engine has a switch: WebRTC, media capture and link preconnect on WebKitGTK, WebRTC IP handling on WebView2, and keep forged binding calls from flooding the launcher's logs (SBOX-04, part of SBOX-03; D-09, D-10, D-11, D-15, D-19, D-20).

Purpose: the napplet CSP sets connect-src 'none', but WebKitGTK 2.52 still exposes navigator.mediaDevices by default and opens a TCP connection for link preconnect (RESEARCH C4, C5). Engine settings are the only NIP-5D-compatible way to turn those off.
Output: harden_{linux,windows,other}.go, prepareEngine/hardenEngine call sites, sampled token-miss logging, unit tests, and a gated real-WebKitGTK test whose helpers the 04-05 smoke harness reuses.
</objective>

Facts from the research spike (WebKitGTK 2.52.6, go-webview v0.0.0-20250327021345-7b06ad397f16 / libwebview 0.12.0, purego v0.8.2):
- go-webview exposes Window() unsafe.Pointer (the GtkWindow* on Linux) and no settings or native-handle API; gtk_bin_get_child(Window()) returned the WebKitWebView*, equal to webview_get_native_handle kind 2.
- Signatures that worked through purego.RegisterLibFunc (Go func types): gtk_bin_get_child func(uintptr) uintptr (libgtk-3.so.0); from libwebkit2gtk-4.1.so.0: webkit_web_view_get_settings func(uintptr) uintptr; webkit_settings_set_enable_webrtc func(uintptr, bool); webkit_settings_get_enable_webrtc func(uintptr) bool; webkit_settings_set_enable_media_stream func(uintptr, bool); webkit_settings_get_enable_media_stream func(uintptr) bool; webkit_settings_get_all_features func() uintptr; webkit_feature_list_get_length func(uintptr) uint64; webkit_feature_list_get func(uintptr, uint64) uintptr; webkit_feature_get_identifier func(uintptr) string; webkit_settings_set_feature_enabled func(uintptr, uintptr, bool); webkit_settings_get_feature_enabled func(uintptr, uintptr) bool; webkit_feature_list_unref func(uintptr) (assumed, A8: skip if absent).
- purego.RegisterLibFunc panics on a missing symbol; purego.Dlsym returns an error instead.
- Defaults on 2.52: enable-webrtc false, enable-media-stream TRUE; preconnect leaks a DNS lookup and TCP connect unless the feature LinkPreconnect is off.
- libwebview's WebView2 user data folder is %APPDATA%\<exe name>; the exe is child-<sha256>.exe, so all window kinds of one build share one browser process, and mismatched options fail later windows with ERROR_INVALID_STATE (Pitfall 6). The loader appends WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS to the (null) options libwebview passes.
- Go tests never call webview.New in-process (Pitfall 8): the real child binary runs as a subprocess. Headless WebKit needs WEBKIT_DISABLE_COMPOSITING_MODE=1 and WEBKIT_DISABLE_DMABUF_RENDERER=1 (Pitfall 9).
- The child must not import desktop/internal/webviewlib (it would embed the library); tests copy the generated library file by path instead.
- With stdin at EOF the child's reader calls w.Terminate(), so a child started with an empty stdin opens its window, runs everything before Navigate, and exits.
