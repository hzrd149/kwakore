## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| napplet window → launcher network and memory (resource fetches) | Each URL costs launcher bandwidth and memory |
| napplet window → other napplet windows (INC channels) | Channels hold state in both windows |
| napplet window → Blossom servers and the user's signer (uploads) | Each upload can prompt, sign and send up to 16 MiB |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-36 | Denial of service | bulk resource requests amplifying one envelope into 100 fetches | high | mitigate | per-URL charge against the resource bucket (burst 100, 60/min); TestResourceChargedPerURL |
| T-02-37 | Denial of service | unbounded concurrent fetches per window | medium | mitigate | at most 10 in flight per window (resourceTrack); TestResourceInFlightCap |

| T-02-39 | Denial of service | parallel upload floods (memory, prompts, signer) | medium | mitigate | at most 4 active uploads per window, checked before the async part and again before storing; TestUploadActiveCap |
