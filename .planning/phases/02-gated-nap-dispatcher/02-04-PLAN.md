Gate helper contract (this plan's design, D-02a):
- `c.approve(perm, title, detail, code) (bool, error)`: per-call question; allowed only when the route's gate is PerCall with that perm, or Dynamic listing it. Calls askApproval; sets c.approved on true. The error is always nil until 02-06 makes prompts cancellable and bounded; handlers already treat a non-nil error as "answer with failWith(code)" via `c.failForPrompt(err)`.
- `c.grant(perm, title, detail) (bool, error)`: session question (asked once per session); allowed when the gate is Session with that perm, or Dynamic listing it. Calls c.sessionGrant; sets c.approved on true.
- `c.hasGrant(perm) bool`: check-only Session gate (notify.send never prompts): session grant true, or a rule with Decision allow; sets c.approved on true.
- A helper called with a permission the route did not declare logs at Error ("NAP gate asked outside its declaration"), answers failWith(napErrDenied) and returns false.
- Sinks check c.approved first through `c.sinkAllowed(name)`, which also calls the test hook `napSinkHook(name, approved)` when it is non-nil; refused sinks log at Error, answer failWith(napErrDenied) and return an error (`errSinkRefused`) without side effects.
</context>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NAP handler → user's key (sign, encrypt) | The user's signer acts only after the declared consent |
| NAP handler → OS and network (open link, notify, play, fetch, upload) | Side effects outside the sandbox |
| future handler code → gate layer | A new or edited handler must not be able to skip consent silently |
