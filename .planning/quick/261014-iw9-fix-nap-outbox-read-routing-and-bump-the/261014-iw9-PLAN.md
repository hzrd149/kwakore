<objective>
Fix NAP-OUTBOX read routing so it follows NIP-65 relay lists (the pinned MUST "The shell MUST resolve relay plans according to NIP-65 relay list metadata when available") and never lets a napplet steer the daemon onto a private relay through someone else's relay list (Security MUST), apply the same routing to NAP-RELAY's napRelaysFor, then re-pin NAP-OUTBOX to napplet/naps PR #32 head 8865f73d52a4864afee145f28d26520476273927.

Purpose: the read paths call the sdk's outbox/inbox lookups, which read an in-memory hint database that only network events feed. After a daemon restart a kind 10002 held in the local store yields no hints, so every author is routed to two hardcoded relays (cached for two minutes), the configured fallback is never used, and relays from third-party lists are never public-host checked. The upstream diff 4589a8f9 to 8865f73d has no MUST changes; it rewords the web binding (presence signals availability, already how Kwakore works) and sharpens the fallback SHOULD ("for read targets and for the shell-user's own write set. Fallback never substitutes for a `toInboxes` read relay.").

Output: three focused commits (read routing, NAP-RELAY routing, re-pin), regression tests with stubbed relay lists and checks plus one real-store restart regression, the pin bump across five files and three CONFORMANCE rows.
