Discretion choices (documented in the tasks):
- **Duration syntax.** The value is a Go duration in a fixed ASCII shape: `^(0|([0-9]+(\.[0-9]+)?(ns|us|ms|s|m|h))+)$`, at most 32 bytes, then `time.ParseDuration` and the bounds. A leading sign, a `µs` spelling or a `d` unit is rejected, because Go has no day unit. "7 days" is therefore written `168h`, and the docs say so. Nix checks the same shape and leaves the bounds to the packaged `kwakore validate`, which its configHome derivation already runs.
- **What `0` turns off.** `0` stops only the periodic refresh, per the locked wording "refreshed on an interval (a setting, `0` turns it off)". The install, update and selection hooks still fetch once, and the docs say so.
- **Daemon-only gate.** A hook needs `prefetchNappletSocial()` (serviceConfig != nil, like prefetchNappletIcons) and a running loop. The loop registers its context, and hook refreshes join a wait group that the loop's wait func drains. This is needed because backend shutdown does not wait for backgroundSyncs, and a hook writes to the store.
- **Daemon `TestMain`.** Every daemon test opens the real service with the default (real) relays. A new `backend/daemon/main_linux_test.go` swaps the daemon's `startSocialRefresh` seam for a no-op, so no daemon test runs the loop or the install hooks. One test swaps in a recorder to prove the wiring.
- **Selection hook.** `registry_selection.go` also calls scheduleNappletIconCache when a version selection commits. A selection installs that version, so the social hook goes there too.
- **Offline retry.** When the service is offline at a due tick, the next try is min(interval, 15m) later, so a session that starts before the network does not wait a whole interval.
- **Change detection.** The held event ids of every category are compared before and after a refresh. That catches ingest, NIP-09 deletions, caps and evictions alike. A change of the recorded zap provider counts as a `zaps` change when receipts are held, because it changes what is counted.
- **Event emission.** A status-only change (for example `unavailable`) is not a content change, so it emits nothing.

Excluded by scope: no new RPC methods, no NWC or wallet, no mute list, and no versioning work. A real-relay check (`kwak events` showing `social.updated`) is a manual step for the user.
