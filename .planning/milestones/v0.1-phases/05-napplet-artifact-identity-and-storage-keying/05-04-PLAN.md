<objective>
Key NAP-CONFIG by the same (address, artifact hash) scope as NAP-STORAGE (KEY-02, D-03), name config files by the hex hash of that scope (KEY-04, D-04), and make config pushes and the settings window follow the scope of the napplet they were opened for (RESEARCH Pitfall 7).

Purpose: today napconfig is keyed by napp id with its own lossy file names, so values survive updates (a deliberate deviation NAP-CONFIG forbids: “Persisted values MUST be keyed on the napplet's `(dTag, aggregateHash)` identity per NIP-5D.”) and d values can share a file (CF-2).
Output: scope-keyed napconfig with FileName and Forget, scope-aware handlers, pushes and settings windows, inverted and new tests.
</objective>
