<objective>
Fix the pre-existing shortcut injection the research found (D-21) on Linux: a hostile d can add lines such as a second Exec= to .desktop files through X-Verdana-Napp-ID and the newline-unescaped Exec quoting. After this plan every Linux .desktop file carries an encoded id and every written key refuses or strips control characters, with a hostile-d regression test. 05-12 does the same for the macOS and Windows writers.

D-21 has no requirement ID of its own; it is filed under KEY-03 because the full-address ids D-01 introduces for KEY-03 are what now flows into these files, and this plan makes sure they only ever reach them encoded.
Purpose: with "expose installed apps" on, clicking a crafted napplet's shortcut must never run an attacker's command.
Output: backend launch tokens, token-only Linux writers, a control-character-refusing quoteExecField used by every Linux .desktop writer, regression tests.
</objective>
