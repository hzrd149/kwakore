<objective>
Bound the two places where a napplet's bytes enter the launcher before NAP parsing starts: the desktop child process pipe (both directions) and Android's string hand-off, and remove the last package-init panic on the backend's startup path (`backend/cache.go`).

Purpose: DISP-03 asks for "a cap on lines from the child process", and D-12/D-17 say an overlong line kills only that child; the Go envelope caps in 02-03 only help once a line has been read whole. DISP-05 names `backend/cache.go` explicitly.
Output: new package `desktop/internal/wireline` with tests, `readChild` and the child's stdin reader on it, `backend.MaxInboundWireMsg` used by desktop and by `HandleWireMessage`, and `newCache` without panics.
</objective>

Line framing facts (02-RESEARCH Pattern 5): `json.Encoder.Encode` writes one value plus `\n` and escapes control characters inside strings, so one line is one message. `bufio.Scanner` with `Buffer(buf, max)` rejects a line of exactly `max` bytes, so size it `max+1` (Pitfall 5). If the launcher stops reading without killing the child, the child can block writing to a full pipe and `cmd.Wait()` hangs (Pitfall 6).
