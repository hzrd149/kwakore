<objective>
Slim `.github/workflows/linux.yml` to the Go test lanes, with a release that runs only on tags. Rewrite the CI contract test to pin the new shape. Delete the throwaway CI user-manager helper. Update the docs and the Phase 9 verification records to match.

Purpose: CI failed three runs in a row, all in the systemd and sudo integration lanes and none in Kwakore itself. The repo owner (hzrd149) then decided: "we dont need to test the full linux integrations in the CI, probably just the go tests", and chose "Keep tag-only release". This plan implements that decision exactly:
- `backend` and `child` run on every push and pull request.
- `bundle` (amd64 and arm64) and `release` run only on `v*` tags.
- The graphical (xvfb WebKit), nix, user service and installed artifact lanes are removed.
- `scripts/ci-user-manager.sh` is deleted.
- `scripts/smoke-linux-service.sh` stays as a local developer tool.
- The graphical WebKit tests and TestRPCRealChildGraphical stay in the repo behind their env gates and run only locally, on demand.

Decisions taken here (discretion delegated by the orchestrator):
- **Keep TestRPCRealChildCIContract, renamed TestCIWorkflowContract.** It still protects four things that matter:
  1. The backend job must set the node gate. Without it, the security-relevant host-page and frame-scope tests (`backend/webview/napplet_host_test.go`, `backend/nap_scope_test.go`) would silently skip in CI.
  2. A tag must not publish unless backend, child and bundle passed, and the publish action stays pinned to a commit SHA.
  3. The real-engine gates must not come back in a half-wired form. The old job relied on PASS-line checks to stop silent skips.
  4. The child job must carry the "not run in CI" notice.

  The old string list only pinned what the removed graphical job contained, so it is rewritten rather than deleted. It becomes a small checker that strips comment lines, splits the file into jobs, and is itself tested against mutated copies of the workflow.
- **Triggers:** the `on:` block stays unchanged (push to master/main, `v*` tags, pull_request, workflow_dispatch). The two Go lanes run on all of these, and only bundle and release carry the tag condition. This avoids duplicate runs for pull-request branches.
- **The bundle job stays as it is today,** including its `--bundle-only` smoke and per-arch manifest checks. The only change is the job-level tag condition. The smoke needs no user manager and no sudo.
- **The GSD place to record the superseded must-haves is `09-VERIFICATION.md`.** It goes in the frontmatter `overrides:` (see `$HOME/.claude/gsd-core/references/verification-overrides.md`), with matching row statuses. The executed `09-09-PLAN.md` and `09-11-PLAN.md` are left untouched, because they are historical prompts and their frontmatter is schema-validated.
- **The dead throwaway-manager branch in the smoke script is removed.** It is reachable only under the deleted helper, because it requires an `XDG_RUNTIME_DIR` under `/run/kwakore-ci.*` that only that helper created. Local runs already use the runtime drop-in path, so their behavior is unchanged.

Output: slimmed linux.yml, rewritten contract test, deleted helper, local-only smoke script, updated contributor and audit docs, and Phase 9 records showing the scope change.
</objective>
