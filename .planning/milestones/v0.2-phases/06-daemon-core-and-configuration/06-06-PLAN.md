  <behavior>
    - The first SIGINT or SIGTERM starts one monotonic five-second deadline, gates Begin and RPC, and cancels registry work before waiting for the listener or leases.
    - If all leases return, listener and stores close in order, the data lock is explicitly released, and process exits zero within the grace period.
    - If an operation lease remains held, a real child daemon exits with fixed deadline status no later than the grace deadline plus measured scheduler/test tolerance; closeBackend is never called under the lease and a second process can take the flock only after the first process has exited.
    - A second concurrent signal cannot restart the timer, enter teardown twice, or bypass recovery barriers.
  </behavior>
  <action>Implement D-03 at the foreground process boundary. Split Service.Close into an idempotent begin-shutdown operation that atomically sets closing/ready, refuses new leases, and cancels work, followed by a lease drain and then normal closeBackend/flock release. Keep in-process Service.Close lease-safe and unbounded for library callers; do not add the old timeout branch that closes backend stores under active work. In main, on the first shutdown signal start a monotonic five-second watchdog before any blocking listener or service close. Begin service shutdown immediately, stop accepting socket clients and close existing client connections to propagate cancellation, then wait for listener handlers and service leases. Ensure listener.Close cannot delay cancellation as the current defer order does. If drain finishes before deadline, stop watchdog exactly once, call closeBackend only after work.Wait returns, release lock, and return zero. On expiry, emit a fixed sanitized stderr deadline line and terminate the foreground process with a documented nonzero exit code, such as 124, via os.Exit; os.Exit bypasses Go defers, so this path must not call closeBackend or unlock while a lease is live. Kernel process teardown closes store descriptors and releases flock; the next daemon runs Plan 05 recovery before readiness. Route daemon.Run through the same orderly begin/drain ordering for integration callers, but keep hard exit confined to the foreground executable. Use a child-process test hook or helper mode to hold a real lease without exposing a production RPC for this purpose. The test must invoke the production signal coordinator, not a mock timer. Avoid stating an absolute real-time guarantee independent of OS scheduling or an uninterruptible kernel state: the five seconds is a user-space grace deadline, with process exit observed within a small explicit scheduling tolerance in CI.</action>
